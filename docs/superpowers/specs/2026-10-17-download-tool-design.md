# 本地下载器设计（aria2 + Rust/egui）

**日期：** 2026-10-17  
**状态：** 待实现  
**仓库：** `download-tool`

## 1. 背景与目标

网站提供文件下载；文件过大时浏览器下载不稳定、难管理。目标：

- 网站按**可配置大小阈值**决定走浏览器或本地下载器
- 大文件自动唤起本机下载器；未安装则引导安装
- 下载器基于 **aria2**，UI 为 **Rust + egui**
- 支持 **Windows / macOS / Linux**
- 网站**无登录**；服务器账号密码与磁盘路径**永不下发**到浏览器或下载器
- 文件在服务器侧通过 **HTTP**（非 HTTPS）提供下载

## 3. 总体架构

采用「本机守护进程 + egui 壳」：

```
网站前端 + JS SDK
       │
       │ 1) POST /api/download-ticket (fileId) → 短时 downloadUrl
       │ 2) 大文件：探测本机 → 投递任务 / 协议唤起 / 安装引导
       ▼
本地下载器 (Rust + egui)
  · 托盘 + 单实例
  · HTTP API @ 127.0.0.1
  · 自定义协议 dltool://
  · 内嵌 aria2c (JSON-RPC)
       │
       │ HTTP GET downloadUrl（支持 Range）
       ▼
网站 HTTP 出站（鉴权后 sendfile / X-Accel-Redirect）
       │
       ▼
文件存储（仅服务端可访问）
```

**小文件：** `size < sizeThreshold` 时 SDK 走浏览器下载，不唤起本机程序。

## 4. 下载协议说明

下载器**不**使用 FTP/SFTP，也**不**直连磁盘。

| 环节 | 协议 |
|------|------|
| 网站 ↔ 本机下载器 | `http://127.0.0.1`（任务投递）+ `dltool://`（唤起） |
| 下载器 ↔ 文件字节流 | **HTTP**（aria2 作为 HTTP 客户端，多连接 + Range 续传） |
| 后端 ↔ 存储 | 仅服务端内部 |

与浏览器下大文件的区别：同一条 HTTP 临时链接，换用 aria2 引擎（多连接、断点、队列、限速、独立进程），而非换传输协议。

明文 HTTP 下签名 URL 可能被同网段窃听；适用于内网/可信环境。日后升级 HTTPS 时，接口字段可保持不变。

## 5. 网站后端规范（本期只文档）

### 5.1 文件标识

- 对外一律使用不透明 **`fileId`**
- 目录列表不返回服务器绝对路径
- 禁止客户端传绝对路径做下载（防路径穿越）

### 5.2 目录列表

```http
GET /api/files?parentId=...
```

响应示例：

```json
{
  "items": [
    {
      "fileId": "f_01hxyz",
      "name": "data.zip",
      "size": 1234567890,
      "isDir": false,
      "updatedAt": "2026-10-17T12:00:00Z"
    }
  ]
}
```

### 5.3 签发临时下载票

```http
POST /api/download-ticket
Content-Type: application/json

{ "fileId": "f_01hxyz" }
```

响应示例：

```json
{
  "fileId": "f_01hxyz",
  "fileName": "data.zip",
  "size": 1234567890,
  "downloadUrl": "http://your-host/d/<signed-token>",
  "expiresAt": 1730000000
}
```

要求：

- `downloadUrl` 短时有效（建议默认 15 分钟，可配置 5–30 分钟）
- 下载端点校验签名与过期时间
- 响应必须支持 **`Range` / `206 Partial Content`**（aria2 多连接与断点续传依赖）
- 不得返回服务器账号、密码、磁盘根路径

### 5.4 大文件出站稳定性

**禁止**业务进程将整文件读入内存再写出。

推荐：

1. 应用（或网关）只做鉴权/验签
2. 通过 Nginx `X-Accel-Redirect`（或 Caddy/等价机制）将文件交给 Web 服务器 `sendfile` 输出
3. 配置足够大的代理/读超时，避免长传被掐断
4. 可配置：单 IP 并发、带宽限速、全局限流
5. 日志只记 `fileId`、状态码、耗时，不记文件内容

若必须由应用输出：按块流式读写（如 64KB–1MB），并正确实现 Range。

### 5.5 站点配置（供 SDK）

```json
{
  "sizeThreshold": 104857600,
  "installUrl": "http://your-host/download-tool",
  "localPort": 29128,
  "protocol": "dltool"
}
```

- `sizeThreshold`：默认 **100MB**，由网站配置
- `localPort`：与客户端约定默认端口
- `installUrl`：未安装时的引导页

## 6. 本机 HTTP API

仅监听 **`127.0.0.1`**，不对公网网卡开放。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/health` | SDK 探测：已安装且进程在跑 |
| POST | `/v1/tasks` | 投递下载任务 |
| GET | `/v1/tasks` | 任务列表（可选，调试用） |

`POST /v1/tasks` 请求体：

```json
{
  "url": "http://your-host/d/<signed-token>",
  "fileName": "data.zip",
  "size": 1234567890,
  "referrer": "http://your-host/files",
  "userAgent": "Mozilla/5.0 ..."
}
```

成功：`{ "taskId": "..." }`，任务入队并由 aria2 开始下载。

**端口冲突（首版定案）：** 固定监听 `127.0.0.1:29128`。若端口已被占用且不是本应用单实例，则启动失败并在 UI 中明确提示；不在首版做动态端口协商（避免 SDK 找不到服务）。

## 7. 自定义协议

Scheme：`dltool`

```
dltool://add?url=<urlencode>&fileName=...&size=...
```

- 仅携带已签发的短时 `downloadUrl` 与展示元数据
- 不携带服务器账号密码
- 冷启动：OS 拉起 App → 解析 → 入队
- 已运行：单实例将参数转交给已有进程

**SDK 唤起顺序：**

1. `GET http://127.0.0.1:{port}/health`
2. 通 → `POST /v1/tasks`
3. 不通 → 打开 `dltool://add?...`
4. 仍失败/超时 → 安装引导（`installUrl`）+「我已安装，重试」

## 8. 安全模型

| 原则 | 做法 |
|------|------|
| 凭据不上客户端 | 服务器账号、长期密钥、磁盘根路径仅后端持有 |
| 只认 fileId | 列表与签发均不暴露绝对路径 |
| 短时下载票 | 签名 + 过期；可加并发/IP 限流防刷链 |
| 本机 API 隔离 | 仅 127.0.0.1 |
| 协议最小化 | `dltool://` 不放长期密钥 |
| 明文 HTTP | 接受内网窃听风险；公网场景升级 HTTPS |

无登录站点：下载票过期后需用户在网页再次点击下载重新签发；下载器不存储可无限续期的服务器凭据。

## 9. 桌面客户端

### 9.1 技术选型

- UI：Rust + **egui**
- 引擎：安装包内嵌各平台 **aria2c**，经本地 **JSON-RPC** 控制
- 不依赖用户系统是否已安装 aria2

### 9.2 功能集（首版 = 常用增强）

- 接收任务、多连接 HTTP 下载、进度/速度展示
- 暂停 / 继续 / 取消
- 选择默认保存目录
- **队列**、**断点续传**、**限速**（全局与单任务）
- **托盘常驻**、可选开机自启、单实例

### 9.3 模块

| 模块 | 职责 |
|------|------|
| RPC 宿主 | 启停 aria2、健康检查、异常重启 |
| 任务管理 | 入队、去重、状态（排队/下载中/暂停/完成/失败） |
| 本地 HTTP | health + tasks |
| 协议处理 | 注册与处理 `dltool://` |
| 设置 | 目录、限速、自启、连接数 |
| UI | egui 主界面 + 托盘菜单 |

### 9.4 平台打包要点

- Windows：协议注册、托盘、安装包
- macOS：协议注册、托盘、dmg（公证属发布阶段）
- Linux：`.desktop` 协议关联；首版可 AppImage（或再补 deb）

### 9.5 错误与体验

| 场景 | 行为 |
|------|------|
| 403/410（票过期） | 任务失败提示；引导回网页重新点下载 |
| 网络中断 | 暂停或自动重试；续传接着下 |
| 磁盘满 / 无权限 | 明确报错，可改目录后重试 |
| 重复投递同一文件 | 不去重入队两次，或提示已在队列中 |

## 10. JS SDK

示例 API：

```js
DownloadTool.download({
  fileId,
  size,
  apiBase,
  config // sizeThreshold, installUrl, localPort, protocol
})
```

逻辑：

1. `size < sizeThreshold` → 向后端取票（如需要）后浏览器下载
2. 否则取票 → 探测本机 → POST 任务 或 `dltool://` 或安装引导
3. 安装引导文案/样式可由站点自定义；SDK 提供默认 UI 或回调

## 11. 安装分发

- 本仓库产出 Win / macOS / Linux 安装产物
- 首版不做应用内自动更新
